# Auto2048

[LiveContainer](https://github.com/LiveContainer/LiveContainer) で動かす 2048 の自走 tweak です。ゲーム内部から 4×4 の盤面を読み、最大 4 手先までの探索で操作方向を決めます。

## 対象・実機確認

- 対象: Ketchapp 2048 **4.0.8** (`com.ketchapp.2048`)、通常ゲームの 4×4 盤面。
- arm64 / iOS 13.0 以降向け。ゲームの更新や LiveContainer の環境により動作しなくなる場合があります。
- v3 で実機上の自走と 2048 タイルの達成を一度確認しています。毎回の達成、他の環境での動作は保証しません。
- ゲーム本体・IPA・抽出データ・セーブは含みません。利用者自身で用意してください。

## 導入

1. このリポジトリの [`Auto2048.dylib`](Auto2048.dylib) を、LiveContainer の対象アプリの Tweak フォルダに入れ、アプリに割り当てます。旧バージョンがある場合は取り除きます。
2. 必要な署名は使用中の LiveContainer の手順に従ってください。添付バイナリは ad-hoc 署名済みであり、実機では再署名が必要な場合があります。
3. アプリを起動して通常ゲームを開き、右下の `AUTO` ボタンをタップして ON/OFF します。起動時は常に OFF です。

**速度**はボタンの長押しで `x1 → x2 → x4 → MAX` と切り替わります。手を打った後の最低待ち時間は 0.9 / 0.65 / 0.45 / 0.30 秒。探索やアニメーションにより実際の間隔は長くなる場合があります。速度のみ保存されます。

## 注意

- 盤面を自動操作するため、スコアやセーブに変更が生じます。必要なら事前にバックアップしてください。
- 広告やポップアップは完全には検出できません。表示前に AUTO を OFF にし、閉じてから再開してください。自動リスタートやポップアップの自動操作はありません。
- 達成画面では `AUTO PAUSE` になり、AUTO が ON のまま「続ける」を押すと自走が再開します。停止したいときは OFF にしてください。
- チャレンジ・対戦などの別モードは対象外です。

## 仕組み

JIT・インラインフックを使わず、Unity の IL2CPP API を名前で解決します。`Grid.GetCellValue` で盤面を読み、`GameManager.HandleSwipe(Vector2Int)` に方向を渡します。盤面を直接書き換える方式ではありません。UI 操作と IL2CPP 解決の方式は [LCAC-A](https://github.com/mar1mo-41414/LCAC-A) を参考にしています。

ソルバーは最大 **4 手**の expectimax 型探索を行います。各手の後に 2 が 90%、4 が 10% で出ると仮定します（ゲーム内部での確率を確認したものではありません）。空きマスが 4 個以下なら全位置、5 個以上なら最大 4 位置をサンプリングするため、全パターンの厳密な探索ではありません。途中で合法手がなくなった場合もそこで打ち切ります。

空きマスの数、数字の隣接関係、単調性、最大タイルの角配置、角からの蛇行順を評価します。蛇行配置は回転・反転した 8 方向から選び、角を固定しません。

IL2CPP の盤面取得と入力はメインスレッド、探索はバックグラウンドで行います。操作直前に盤面・ゲーム状態を読み直し、探索中に盤面が変わった場合は結果を破棄します。OFF やバックグラウンド移行でも実行中の結果は無効化します。

## 状態表示

| 表示 | 意味 |
| --- | --- |
| `OFF` / `ON` | 自走 OFF / 操作済み |
| `THINK` | 探索中 |
| `STALE` | 盤面が変化したため探索結果を破棄し、次回読み直し |
| `MODE` | 対象外のモード |
| `PAUSE` | ゲームが停止中 |
| `V_MOVE` | タイルのアニメーション待ち |
| `END` / `SIZE` / `DATA` / `ERR` | 合法手なし / サイズ不一致 / 想定外の盤面値 / 内部エラー。自動停止 |
| `I_API` / `I_UNITY` / `I_CLASS` / `I_METHOD` | IL2CPP の初期化・解決待ち |
| `F_MGR` / `G_NULL` / `V_NULL` / `V_GRID` | 管理オブジェクトや盤面・表示情報の待機 |
| `F_EXC` / `G_EXC` / `V_EXC` | 内部呼び出し中の例外 |

## ビルド

[Theos](https://theos.dev/) と iOS SDK を用意し、リポジトリ直下で実行します。

```sh
make
```

生成物は通常 `.theos/obj/` 以下です。配布バイナリは Linux 上の clang / ld64.lld と iOS SDK を用いてビルドしたものです。環境に応じて再署名してください。

## ソルバーテスト

```sh
cc -O2 tests/solver_test.c Sources/Solver.c -lm -o /tmp/2048-test && /tmp/2048-test
cc -O2 tests/internal_test.c -lm -o /tmp/2048-internal && /tmp/2048-internal
# 任意: ソルバー単体の簡易ゲームシミュレーション
cc -O2 tests/simulate.c Sources/Solver.c -lm -o /tmp/2048-sim && /tmp/2048-sim 3 5000
```

ホスト環境でユニットテストと 10,000 盤面の内部移動シミュレーション比較を実施済みです。簡易シミュレーション3回の最大タイルは 2048・4096・2048 でした。これは少数の試行であり、実機での到達率を示すものではありません。
