# Auto2048 — LiveContainer 用 2048 自走 tweak

[English README →](README-EN.md)

[LiveContainer](https://github.com/LiveContainer/LiveContainer) で動かす **2048** (`com.ketchapp.2048`) の通常ゲームを自動操作する tweak (dylib) です。
最大 8 手先 (終盤) まで探索してスワイプの方向を決めます。**2048 の到達は保証しません。**

- **盤面の自動操作** — 空きマス・単調性・蛇行配置などを見て、合法手の中から 1 手を選びます。
  空きマスは数だけでなく、つながっているか (使える形か) も見ます。
  最大タイルの 2 枚が合体できるときは、必ず合体させる手を選びます。
- **速度の切り替え** — ボタンの長押しで `x1` / `x2` / `x4` / `MAX` (`MAX` は待ち時間なしで、計算とタイルのアニメーションの分だけ)。
- **深く読む** — 1 手あたりの計算量に上限を決めて、その範囲で 4〜6 手先まで読みます。
  空きマスが 4 個以下になった終盤は上限を 4 倍に広げ、最大 8 手先まで読みます
  (終盤は分岐が小さいので、時間はほとんど増えません)。
- **出現タイルを 4 に固定 (実験的)** — ゲーム側の「4 の出る確率」を探して書き換えます。
  効かない環境では自動で 2 / 4 に戻ります (docs/TROUBLESHOOTING.md)。
- **状態の表示** — ボタンに `THINK` / `STALE` / `PAUSE` などの状態を出します。意味と対処は [docs/TROUBLESHOOTING.md](docs/TROUBLESHOOTING.md)。
- 対象は 2048 **4.0.8** の通常ゲーム (4×4) のみです。チャレンジ・対戦には対応していません。

## 動作確認状況

| 項目 | 状況 |
| --- | --- |
| 実機 (LiveContainer) | v3.5 で自走を確認。**8,192 到達** (2026-11-03)、4,096 は複数回 |
| 2048 のバージョン | 4.0.8 のみ (他のバージョンは未確認) |
| ゲームモード | 通常ゲーム (4×4) のみ |
| 広告・ポップアップ | 検出しません (手動で OFF / ON) |
| ホスト側シミュレーション (出現 2 / 4、v3.5 まで) | 16 回中 8 回が 4,096 到達 (平均最大タイル 2,976) |
| ホスト側シミュレーション (出現 4 固定、v3.9) | 24 回中 18 回が 8,192 到達 (平均最大タイル 7,168) |
| ホスト側シミュレーション (出現 4 固定、v3.9・9,000 手まで) | 2 回とも **16,384 到達** (318,160 / 323,984) |

v3.5 は出現タイルを 4 に固定するため、到達タイルが 1 段ぶん伸びます (2 の世界の 4,096 が、
4 の世界の 8,192 に相当)。画面のタイル表示は 2 のままですが、ゲームの計算は 4 で進みます
(2 と 2 が合体して 8 になるのがその証拠)。詳しくは [docs/TROUBLESHOOTING.md](docs/TROUBLESHOOTING.md)。

シミュレーションは試行回数が少なく、実機での到達率を示すものではありません。
v3.9 で終盤を深く読むようにしたため、1 手あたりの時間は v3.8 の 2.5 倍前後になっています
(ホストで平均 60〜75ms、終盤ほど長くなります)。
実機で確認したのは**作者の環境 1 台**です。別の端末・バージョンでの結果は Issue で教えてもらえると助かります。

## ダウンロード

[Releases](../../releases/latest) から `Auto2048.dylib` を取得してください。
ゲーム本体・IPA は含まれていません。

## 使い方

1. LiveContainer で 2048 の Tweak フォルダに `Auto2048.dylib` を入れて起動します。旧版がある場合は外してください。
2. 通常ゲームを開くと、右下に `AUTO` ボタンが表示されます (起動時は OFF)。

### AUTO ボタン

| 操作 | 動作 |
| --- | --- |
| タップ | ON / OFF |
| 長押し | 速度切り替え (`x1` → `x2` → `x4` → `MAX`) |

- 速度だけが保存され、ON / OFF は保存されません (起動時は常に OFF)。
- `THINK` は探索中、`PAUSE` はゲーム停止中、`STALE` は盤面が変わって探索結果を捨てた状態です。どれも正常な表示です。
- 2048 の達成画面では `PAUSE` になります。AUTO が ON のまま「続ける」を押すと自走が再開します。

### RETRY ボタン

| 操作 | 動作 |
| --- | --- |
| タップ | ON / OFF (起動時は OFF) |

- ON のあいだ、**ゲームオーバーになるたびに「もう一度始める」を自動で押して続行**します。
  オフにするまで繰り返します。
- ON にすると AUTO も ON になります (ゲームオーバーは自走中にしか起きないため)。
- ゲームオーバーの記録は、再挑戦するたびに 1 ゲームずつファイルに残ります。

### ゲームオーバーの記録

ゲームオーバーになると、最終盤面をアプリの `Documents/LCAC-2048_over.log` に追記します。
1 ゲームにつき 1 ブロックで、**dylib の版・時刻・スコア・手数・盤面**が残ります。

```
2026-11-05 15:56:23 +0900 v3.9-1 score=75344 moves=3821
  2048    512    128      4
   256   1024   2048   4096
    32    128    512    256
     4      8     64     32
```

- `moves=` はそのゲームで送ったスワイプの回数です (再挑戦すると 0 から数え直します)。
  途中から装着したゲームでは、装着した時点からの回数になります。
- 盤面は実際の値です (画面に 2 と出ているタイルも、書き換え後は 4 として記録されます)。
- **盤面の 1 行目は画面の一番下の行**です (ゲームの座標が下から始まるため)。
- スコアを取得できなかった場合は `score=-1` になります。盤面は記録されます。
- ファイルは追記されていくので、同じファイルに過去のゲームが残ります。
- 取得方法は [docs/TROUBLESHOOTING.md](docs/TROUBLESHOOTING.md) (「ゲームオーバーのログ」) に書いています。

### 実行ログ

`[2048-auto] ...` のログは **`Documents/LCAC-2048.log` にだけ**書きます (コンソールには出しません。
1 MB を超えたら作り直します)。アプリ自身のログ (広告 SDK・解析) は入れないので、このファイルだけで
不具合の切り分けができます。同じ行が続く場合は 100 回ごとに 1 行へまとめ、20,000 行で打ち切ります。

さらに、**2,048 / 4,096 / 8,192 … を作れた時点**で、そのときのスコア・手数・盤面を 1 行で残します。

```
[2048-auto] milestone tile=8192 score=147528 moves=3210 board 16,4,128,8192 | 8,64,256,4096 | ...
```

`board` はゲームオーバーの記録と同じ並び (1 行目が画面の一番下) です。

**500 手ごと**にも同じ形の `progress moves=… score=… board …` を残します (崩れ始めた位置を見るため)。
ゲームオーバー時には `spawns miss=… count … chance …` (出現位置の回数と、そのマスが空いていた回数) も残ります。

### うまく動かないとき

ボタンが出ない、`I_CLASS` や `F_EXC` のまま止まる、広告で止まる、といった症状は
**[docs/TROUBLESHOOTING.md](docs/TROUBLESHOOTING.md)** にまとめてあります。
表示される状態の意味と、そのとき何をすればよいかが引けます。

## 注意

- 広告やポップアップは完全には検出できません。表示前に AUTO を OFF にし、閉じた後に再開してください。
  広告自体を消したい場合は [LCAB](https://github.com/mar1mo-41414/LCAB) などを併用してください。
- 自動操作でスコアやセーブが変わります。必要なら事前にバックアップしてください。
- チャレンジ・対戦、4×4 以外の盤面、自動リスタート、自動ポップアップ操作には対応していません。
- ゲームの内部クラス・メソッドを使うため、ゲームや LiveContainer の更新で動かなくなる場合があります。
  必要な再署名は使用環境の手順に従ってください。
- ゲーム本体・抽出データ・セーブはこのリポジトリに含めていません。

## ビルド

[Theos](https://theos.dev) と iOS SDK が必要です。

```bash
make FINALPACKAGE=1
```

生成された `Auto2048.dylib` は通常 `.theos/obj/` 以下にあります。環境に応じて署名してください。

`vX.X` 形式のタグを push すると、GitHub Actions が macOS 上でビルドし、その dylib を Release に添付します。
リポジトリにバイナリは置いていません (配布は Releases のアセットのみ)。

## テスト

Theos は不要です (ホストの C コンパイラだけで動きます)。

```bash
make test        # 単体テスト + 10,000 盤面の移動処理比較
make simulate    # 簡易シミュレーション (3 ゲーム × 5,000 手。数分かかります)
```

個別に実行する場合:

```bash
cc -O2 -Wall -Wextra tests/solver_test.c Sources/Solver.c -lm -o /tmp/solver-test && /tmp/solver-test
cc -O2 -Wall -Wextra tests/internal_test.c -lm -o /tmp/internal-test && /tmp/internal-test
cc -O2 -Wall -Wextra tests/simulate.c Sources/Solver.c -lm -o /tmp/sim && /tmp/sim 3 5000
```

同じ内容を GitHub Actions (`.github/workflows/tests.yml`) で実行しています。
`Engine.m` / `Controller.m` は iOS SDK と実機が要るため、CI ではビルドしていません。

## スコアログを盤面画像にする

`Documents/LCAC-2048_over.log` の 1 ゲーム分から、ゲームと同じ見た目の盤面画像 (PNG / SVG) を作る
スクリプトがあります。スコアも画像に入ります。

```bash
python3 tools/board_image.py LCAC-2048_over.log --list      # 記録の一覧
python3 tools/board_image.py LCAC-2048_over.log             # 最後のゲームを PNG に
python3 tools/board_image.py LCAC-2048_over.log --block 12  # 12 番目のゲーム
pbpaste | python3 tools/board_image.py -                    # 1 ブロックだけ貼り付けて渡す
```

- PNG は Pillow が必要です (`pip install pillow`)。無い場合は SVG で出るので、ブラウザや
  Quick Look で開けます (`--format svg` で明示もできます)。
- **盤面の向き**: ログはゲームの座標順 (1 行目が画面の最下段) で書かれているため、
  画像では上下を反転して画面と同じ向きに描きます。ログと同じ順で見たいときは `--raw-order`。
- 画像の数字はログの値そのもの (ゲームの内部値) です。画面と同じにしたいときは `--spawn2` を付けると、
  **4 のタイルだけ 2 と表示**します (4 固定はセルを 2 → 4 に書き換えるが、画面は描き直されないため、
  出現した 4 のマスだけ 2 のまま見える)。他のタイルは内部値と画面の数字が一致します。
- `--scale 2` で 2 倍の大きさ、`--out FILE` で出力先を指定できます。
- 配色は**ゲーム本体 (`com.ketchapp.2048` 4.0.8) の実機スクリーンショットから採取**した値です
  (タイル・盤面の枠・空きマス・背景)。16,384 以上だけは未採取なので濃いグレーで描きます。
