# ARCHITECTURE

Auto2048 v3 の仕組み。対象は **2048 4.0.8** (`com.ketchapp.2048`) の通常ゲーム、4×4 盤面です。

## 方針

- UnityFramework の IL2CPP API を `dlsym` で名前解決します。JIT やインラインフック、ゲームバイナリへの書き換えは行いません。
- ゲーム内部の取得と入力はメインスレッド上で行い、探索だけをバックグラウンドで実行します。
- 解析したゲームの内部クラス・メソッド名に依存します。バージョン変更後の互換性は保証しません。
- UI と IL2CPP のアプローチは [LCAC-A](https://github.com/mar1mo-41414/LCAC-A) を参考にしています。ゲーム本体やその抽出データは含めません。

## ゲーム側の構造

| 対象 | 用途 |
| --- | --- |
| `Game2048.GameManager` | `UnityEngine.Object.FindFirstObjectByType(Type)` で取得。`_currentGame` と `HandleSwipe(Vector2Int)` を利用 |
| `Game2048.GameModes.RegularGame` | 通常ゲームかどうかと `GameActive` を確認 |
| `Game2048.GameModes.GameMode` | `get_Grid()` で盤面を取得 |
| `Grid` | `get_Size()` と `GetCellValue(Vector2Int)` で 4×4 の各マスを読む |
| `GridViewManager` | 表示中の `_grid` が取得した盤面と一致し、`IsAnyTileMoving()` が false であることを確認 |

`FindFirstObjectByType` には引数 1 個のジェネリック版もあるため、名前・引数数だけでなく **非ジェネリック版**を選びます。v2 ではこれにより、実機で管理オブジェクト取得時に出た `F_EXC` の有力な原因を修正しました。

`il2cpp_runtime_invoke` でゲームのメソッドを呼び、例外を確認します。フィールドも IL2CPP API を通じて名前で取得し、盤面そのものを直接書き換えず、ゲームの `HandleSwipe` に方向を渡します。

## 探索

`Sources/Solver.c` は、各方向の移動と合体を盤面のコピー上で計算し、最大 **4 回の自分の操作**を先読みする expectimax 型探索を行います。途中で合法手がない場合はそこで打ち切ります。

- 新しいタイルは 2 が 90%、4 が 10% で出ると仮定します。ゲーム側での確率は確認していません。
- 空きマスが 4 個以下なら全位置、5 個以上なら最大 4 位置を選んで確率を近似します。選択位置は盤面ハッシュにより回転させます。
- このため、4 手先の全出現パターンを厳密に網羅するわけではありません。盤面・深さ・ノード種別を使う探索内キャッシュで再計算も抑えます。
- 盤面評価は空きマス、数字の単調性、隣接する数字の差、合体候補、最大値の角配置、角からの蛇行順を考慮します。蛇行順は回転・反転した 8 向きから最良を選び、特定の角には固定しません。
- 明示的な「2048 になったら停止」はなく、通常ゲームを続行するための方策です。2048 達成やゲームオーバー回避は保証しません。

## スレッドと安全確認

1. `CADisplayLink` のメインスレッドで対象モード・ゲーム状態・盤面・表示中の盤面・アニメーションを確認し、16 マスを読み取ります。
2. コピーした数値だけをバックグラウンドのソルバーに渡します。IL2CPP オブジェクトにバックグラウンドからアクセスしません。
3. メインスレッドに戻ったら、AUTO が ON のままでアプリがアクティブなことを確認します。OFF やバックグラウンド移行時は探索結果を無効化します。
4. ゲーム・盤面インスタンス、ゲーム状態、アニメーション、16 マスを再確認し、変化していれば `STALE` 等を表示して操作を行いません。
5. 結果が現在も合法なら `HandleSwipe` を呼びます。ゲームオーバーや達成画面ではゲーム側の状態により `PAUSE` になる場合があります。

## AUTO ボタンと状態

起動時 OFF。タップで ON/OFF、長押しで速度を切り替えます。速度は保存されますが ON/OFF は保存されません。操作後の最低待ち時間は x1 = 0.9 秒、x2 = 0.65 秒、x4 = 0.45 秒、MAX = 0.30 秒です。探索時間・アニメーション等により実際の間隔は長くなります。

| 表示 | 意味 |
| --- | --- |
| `OFF` / `START` / `ON` | 自走停止 / 開始直後 / 操作済み |
| `THINK` | 盤面を探索中 |
| `STALE` | 盤面等が変化したため結果を破棄 |
| `MODE` / `PAUSE` | 対象外モード / ゲームが非アクティブ |
| `V_MOVE` / `V_GRID` / `V_NULL` | タイル移動待ち / 表示盤面の不一致 / 表示側未取得 |
| `I_API` / `I_UNITY` / `I_CLASS` / `I_METHOD` | IL2CPP の API・初期化・クラス・メソッド解決待ち |
| `F_MGR` / `G_NULL` | 管理オブジェクト / 盤面が未取得 |
| `F_EXC` / `G_EXC` / `V_EXC` | 対応する内部呼び出し中に例外 |
| `END` / `SIZE` / `DATA` / `ERR` | 合法手なし / 対象外サイズ / 想定外の盤面値 / 内部エラー。自動停止 |

`Sources/Controller.m` と `Sources/Engine.m` に実装があります。広告・ポップアップの完全な検出はありません。例外や解決失敗は `NSLog` に出力する箇所がありますが、専用の Documents ログファイルは作成しません。

## 検証

```bash
cc -O2 tests/solver_test.c Sources/Solver.c -lm -o /tmp/2048-test && /tmp/2048-test
cc -O2 tests/internal_test.c -lm -o /tmp/2048-internal && /tmp/2048-internal
cc -O2 tests/simulate.c Sources/Solver.c -lm -o /tmp/2048-sim && /tmp/2048-sim 3 5000
```

ホスト側で単体テストと 10,000 盤面の移動処理比較を実施。2 / 4 の出現率を 90 / 10 とする簡易シミュレーション 3 回で、v3 の最大タイルは 2048・4096・2048 でした。少数の試行であり、実機での到達率を示すものではありません。実機では v3 の自走と 2048 達成を 1 回確認しています。
