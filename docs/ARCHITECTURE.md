# ARCHITECTURE

Auto2048 v3 の仕組み。対象は **2048 4.0.8** (`com.ketchapp.2048`) の通常ゲーム、4×4 盤面です。
利用者向けの症状別の対処は [TROUBLESHOOTING.md](TROUBLESHOOTING.md)、開発の経緯は [../HISTORY.md](../HISTORY.md) にあります。

## 方針

- UnityFramework の IL2CPP API を `dlsym` で名前解決します。JIT やインラインフック、ゲームバイナリへの書き換えは行いません。
- ゲーム内部の取得と入力はメインスレッド上で行い、探索だけをバックグラウンドで実行します。
- 解析したゲームの内部クラス・メソッド名に依存します。バージョン変更後の互換性は保証しません。
- UI と IL2CPP のアプローチは [LCAC-A](https://github.com/mar1mo-41414/LCAC-A) を参考にしています。ゲーム本体やその抽出データは含めません。

## 構成

| ファイル | 役割 |
| --- | --- |
| `Sources/Controller.m` | `AUTO` ボタン (タップ / 長押し)、`CADisplayLink` のループ、速度設定の保存、状態表示 |
| `Sources/Engine.m` | IL2CPP のシンボル解決、ゲームオブジェクトの取得、盤面の読み取りと `HandleSwipe` の呼び出し |
| `Sources/Solver.c` | 移動・合体のシミュレーションと expectimax 探索 (ゲーム側に依存しない純 C) |
| `tests/` | ホスト側で動くソルバーのテストと簡易シミュレーション |

## ゲーム側の構造

| 対象 | 用途 |
| --- | --- |
| `Game2048.GameManager` | `UnityEngine.Object.FindFirstObjectByType(Type)` で取得。`_currentGame` と `HandleSwipe(Vector2Int)` を利用 |
| `Game2048.GameModes.RegularGame` | 通常ゲームかどうかと `GameActive` を確認 |
| `Game2048.GameModes.GameMode` | `get_Grid()` で盤面を取得 |
| `Grid` | `get_Size()` と `GetCellValue(Vector2Int)` で 4×4 の各マスを読む |
| `GridViewManager` | 表示中の `_grid` が取得した盤面と一致し、`IsAnyTileMoving()` が false であることを確認 |

`il2cpp_runtime_invoke` でゲームのメソッドを呼び、例外を確認します。フィールドも IL2CPP API を通じて名前で取得し、
盤面そのものを直接書き換えず、ゲームの `HandleSwipe` に方向を渡します。

### `FindFirstObjectByType` の落とし穴

`FindFirstObjectByType` には引数 1 個のジェネリック版 `<T>(FindObjectsInactive)` もあります。
名前と引数数だけで引くとそちらを掴むため、`il2cpp_class_get_methods` を回して
**非ジェネリック (引数が `System.Type`) の版**を選びます。
v2 ではこれにより、実機で管理オブジェクト取得時に出た `F_EXC` の有力な原因を修正しました。

## 探索

`Sources/Solver.c` は、各方向の移動と合体を盤面のコピー上で計算し、最大 **4 回の自分の操作**を先読みする
expectimax 型探索を行います。途中で合法手がない場合はそこで打ち切ります。

- 新しいタイルは 2 が 90%、4 が 10% で出ると仮定します。ゲーム側での確率は確認していません。
- 空きマスが 4 個以下なら全位置、5 個以上なら最大 4 位置を選んで確率を近似します。選択位置は盤面ハッシュにより回転させます。
- このため、4 手先の全出現パターンを厳密に網羅するわけではありません。盤面・深さ・ノード種別を使う探索内キャッシュで再計算も抑えます。
- 盤面評価は空きマス、数字の単調性、隣接する数字の差、合体候補、最大値の角配置、角からの蛇行順を考慮します。
  蛇行順は回転・反転した 8 向きから最良を選び、特定の角には固定しません。
- 明示的な「2048 になったら停止」はなく、通常ゲームを続行するための方策です。2048 達成やゲームオーバー回避は保証しません。

## スレッドと安全確認

1. `CADisplayLink` のメインスレッドで対象モード・ゲーム状態・盤面・表示中の盤面・アニメーションを確認し、16 マスを読み取ります。
2. コピーした数値だけをバックグラウンドのソルバーに渡します。IL2CPP オブジェクトにバックグラウンドからアクセスしません。
3. メインスレッドに戻ったら、AUTO が ON のままでアプリがアクティブなことを確認します。OFF やバックグラウンド移行時は探索結果を無効化します。
4. ゲーム・盤面インスタンス、ゲーム状態、アニメーション、16 マスを再確認し、変化していれば `STALE` 等を表示して操作を行いません。
5. 結果が現在も合法なら `HandleSwipe` を呼びます。ゲームオーバーや達成画面ではゲーム側の状態により `PAUSE` になる場合があります。

無効化は `epoch` のカウンタで行います。`AUTO` の ON / OFF、前面から外れたとき (`UIApplicationWillResignActiveNotification`)、
探索の開始時に `epoch` を進め、戻ってきたときの値が違えば結果を捨てます。

## AUTO ボタンと状態

起動時 OFF。タップで ON/OFF、長押しで速度を切り替えます。速度は保存されますが ON/OFF は保存されません。
操作後の最低待ち時間は x1 = 0.45 秒、x2 = 0.32 秒、x4 = 0.22 秒、MAX = 0.15 秒です。
探索時間・アニメーション等により実際の間隔は長くなります。

状態表示は `Sources/Controller.m` の `status`、ゲーム側の状態は `Sources/Engine.m` が返す文字列です。
表示ごとの意味と対処は [TROUBLESHOOTING.md](TROUBLESHOOTING.md#状態表示の一覧) にまとめています。
`END` / `ERR` / `DATA` / `SIZE` では自動停止します。

ボタンは前面のウィンドウの右下に固定し、ウィンドウが変わったとき (画面遷移・回転) に付け直します。
広告・ポップアップの完全な検出はありません。例外や解決失敗は `NSLog` に出力する箇所がありますが、
専用の Documents ログファイルは作成しません。

## 検証

```bash
make test        # 単体テスト + 10,000 盤面の移動処理比較
make simulate    # 簡易シミュレーション (3 ゲーム × 5,000 手)
```

ホスト側で単体テストと 10,000 盤面の移動処理比較を実施。2 / 4 の出現率を 90 / 10 とする簡易シミュレーション 3 回で、
v3 の最大タイルは 2048・4096・2048 でした。少数の試行であり、実機での到達率を示すものではありません。
実機では v3 の自走と 2048 達成を 1 回確認しています。

## 未対応・既知の制限

- チャレンジ・対戦モード、4×4 以外の盤面。
- 自動リスタート、広告・ポップアップの自動操作。
- 2048 4.0.8 以外のバージョン (内部クラス名・メソッド名が変わると解決に失敗します)。
- `Engine.m` / `Controller.m` は iOS SDK と実機が必要なため、CI ではビルドもテストもしていません。
