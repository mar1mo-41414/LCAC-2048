# TROUBLESHOOTING

Auto2048 が動かないときの確認手順と、`AUTO` ボタンに出る状態表示の意味です。
対象は **2048 4.0.8** の通常ゲーム (4×4) を [LiveContainer](https://github.com/LiveContainer/LiveContainer) で動かす場合です。
仕組み側の話は [ARCHITECTURE.md](ARCHITECTURE.md) にあります。

## まず確認すること

1. 2048 が **4.0.8** か (他のバージョンは未確認。内部クラス名が変わると動きません)
2. **通常ゲーム (4×4)** を開いているか。チャレンジ・対戦、4×4 以外は対象外です
3. Tweak フォルダに `Auto2048.dylib` が **1 つだけ**入っているか。旧版が残っていると外してください
4. LiveContainer 側で tweak が有効になっているか。再署名が必要な環境では手順どおりに署名したか
5. **起動直後は OFF** です。右下の `AUTO` ボタンをタップしましたか (長押しは速度切替)

## 症状別

### AUTO ボタンが出ない

- 2048 ではなく別のアプリ / 別のウィンドウを見ていませんか。ボタンは前面のウィンドウの右下に出ます。
- dylib が読み込まれていない可能性が高いです。Tweak の置き場所、ファイル名、署名を確認してください。
- 起動直後の数十フレームは描画前にボタンを付け直すため、一瞬消えることがあります。

### ボタンは出るが動かない

ボタンの 2 行目は速度ではなく**状態**を出しています (`AUTO THINK` の `THINK` の部分)。
一覧は下の「状態表示の一覧」を参照してください。よくあるのは次の 3 つです。

| 表示 | 起きていること | 対処 |
| --- | --- | --- |
| `I_CLASS` / `I_METHOD` | ゲーム内のクラス・メソッドが見つからない | 2048 のバージョンを確認。4.0.8 以外なら未対応 |
| `MODE` | 通常ゲーム以外 (チャレンジ・対戦など) を開いている | 通常ゲームを開く |
| `PAUSE` | ゲームが非アクティブ (ポーズ・達成画面・広告) | ゲームに戻る。達成画面なら「続ける」 |

### 広告・ポップアップで止まる

広告やポップアップは検出していません。**表示される前に `AUTO` を OFF にし、閉じたあとに ON に戻してください。**
止まったままの場合は、いったん `AUTO` を OFF → ON にすると再開します。

広告そのものを消したい場合は [LCAB](https://github.com/mar1mo-41414/LCAB) などを併用してください (本プロジェクトの対象外です)。

### `STALE` や `V_MOVE` がよく出る

どちらも正常です。`V_MOVE` はタイルの移動アニメーション待ち、`STALE` は探索中に盤面が変わって結果を捨てた状態で、
次のフレームで自動的に探索し直します。連続して出続ける場合は、ゲームがポーズしていないか確認してください。

### 遅い・反応が鈍い

v3.9 で終盤の探索を深くしたため、1 手あたりの計算時間が増えています (ホストで平均 60〜75ms、
終盤の 1 手は 0.3 秒程度)。速度を優先したい場合は、`Sources/Solver.c` の
`ENDGAME_BUDGET_MULT` を `1` にすると終盤の深掘りを止められ (v3.8 と同じ速さ)、
`NODE_BUDGET` を小さくすると全体が浅くなって速くなります (例: 100000)。

速度を `MAX` にした場合、待ち時間は 0 で、間隔は探索時間とアニメーション待ちだけで決まります。
探索は計算量の上限内で 4〜6 手先 (終盤は最大 8 手先) まで読むため、盤面によって 1 手あたりの時間が変わります。
端末が古い / 他のアプリが重い場合は `x1` や `x2` のほうが安定します。

### アプリが落ちる

- 旧版の dylib が残っていないか確認してください。
- 自動操作でスコアとセーブが変わります。**事前にバックアップ**を取ってから試してください。
- 落ちる直前に `AUTO` が `F_EXC` / `G_EXC` / `V_EXC` / `ERR` を出していないか確認してください (下の一覧)。

### 出現タイルが 4 に固定されない (実験的な機能)

新しいタイルを 4 に固定する機能は、ゲーム側の「4 の出る確率」を探して書き換えています。
効かないときは、無理に動かさず 2 / 4 のまま続行します。

ログの最初に `tweak vX.X: ...` が出ます。まずここで**入れた版が正しいか**を確認してください
(古い dylib を入れたままだと、ここが古い版のままになります)。

画面のタイルが 2 のままなのに、盤面 (ログではなくゲームの計算) は 4 で進むことがあります。
このゲームはセルの値を書き換えても画面を描き直さないためで、**そのままでも強さには影響しません**
(2 と 2 が合体して 8 になるのがその証拠)。

ログ (`[2048-auto]`) で、次のどれが出たかを見てください。

- `spawn forced to 4 via GameManager._xxxx` — 確率フィールドを見つけて書き換えました。
- `grid setter works; spawned 2s are turned into 4s` — フィールドは無かったので、
  出たタイルを 4 に書き換える方式で動いています。
- `no four-chance field and no grid setter; spawns stay 2/4` — この版ではどちらの手も使えず、
  従来通り 2 / 4 で動きます。
- `grid write failed; spawns stay 2/4` — 書き込みを読み直せなかったため、自動で 2 / 4 に戻しました。
- `the game ignores rewritten cells; spawns stay 2/4` — **v3.7 で廃止しました**。
  手で操作したときや、ゲームをやり直したときも「食い違い」に見えてしまうため、
  書き換えを止める判断には使わないことにしました。書き換えが効かない場合は
  画面の 2 と 2 が 4 に合体するので、そこで気づけます。
- `a 2 spawned after forcing; reverting to 2/4` — 確率フィールドの推測が外れたため戻しました。

### 調査ログ（既定ではオフ）

原因を追うための行はコードに残してありますが、**既定では出力しません**。
出すときは `Sources/Engine.m` の `diagEnabled` を `1` にしてビルドしてください。

- `board 1: ...` — 読み取った盤面 (1 行 16 マス、左上から横に 4 つずつ)。最初の 40 回分だけ出ます
- `board 2: ...` — こちらが予想した 1 手後の盤面。`board 1` と食い違うなら、
  ゲームが書き換えを無視しています
- `probe self ... grid ... setter ...` — `self` が 2 種類出れば tweak が二重に読み込まれています
- `cells class ... elem ...` / `name 4 ...` / `name 5 ...` — セルの中身と画面 (`GridViewManager`) の
  クラス・メソッド名 (7bit の数値)
- `view redraw found` / `view redraw called` — 画面の描き直しを呼べたかどうか

既定で出るのは、上の「出現タイルが 4 に固定されない」に挙げた状態の行だけです。

### 再挑戦 (RETRY) が効かない

`RETRY` が ON なのに、ゲームオーバーの画面で止まる場合:

- `restart method not found` → 再開らしい処理が見つかっていません。
- `restart candidate ...` → 再開に使えそうな処理の一覧 (名前・引数の数・戻り値の型を数値で)。
- `restart attempt 2 of 3` → 2 秒ごとに候補を順番に試しています。候補の数も出ます。
- `restart: coroutine started` → その処理はコルーチンで、起動まで行きました。
- `restart took effect: 2 tiles` → 盤面 (ゲームの計算) は新しいゲームに戻りました。
- `field <数値> / <数値>` → 画面側 (`GridViewManager`) が持っている部品の一覧。
- `object <数値>` → その部品の GameObject の名前。
- `panel deactivated` / `object deactivated` → ゲームオーバーの画面を閉じた、という合図です。
  これが出ても画面が残る場合は、閉じる対象が別の部品です。
- `restart entry N kept` → 実際に効いた再開の処理を以後ずっと使う、という合図。
  これが出ないまま 2 回目以降のゲームオーバーで止まるなら、再開の処理が効いていません。
- `paused 5 s; board …` → ゲームが入力を受け付けないまま 5 秒たったときの盤面。
  盤面がまだ動かせる (＝達成画面・広告・メニューなどが出ているだけ) 場合は**何も再開しません**。
  「続ける」を押すか、`AUTO` を切り替えてください。v3.9-7 まではここで強制的に再挑戦していたため、
  達成画面が出た直後にゲームを作り直してしまうことがありました (v3.9-8 で修正)。
- `lose screen <名前>` → 閉じたゲームオーバー画面 (`ClassicRegularGameLoseScreen`)。
- `lose screen hidden (1 of 71 objects)` → 閉じた数。`0` なら見つかっていません。
- `frame 12345 after hide` / `frame 12345 sweep` → ゲームのフレーム番号。
  再挑戦の後にこの数字が進んでいなければ、画面が描き直されていません。
- 再挑戦のあと約 20 秒は走査を続けます。ゲームが後から画面を出し直した場合も閉じます
  (閉じたときだけ `lose screen hidden` が出ます)。
- `hud shown` → ゲームオーバー画面を閉じたあと、スコア・メニュー (`ClassicRegularGameHud`)
  を表示に戻した合図。ゲームはゲームオーバー時に HUD を自分で消すため、こちらで戻します。
  この行が 2 回出ると、通常版とチャレンジ版の HUD を両方出してしまい表示が重なります
  (v3.19 でモードに合うほうだけを出すよう修正)。
- `scene object deactivated` → その部品を非表示にしました。

### 盤面は戻るのにゲームオーバー画面が消えない
盤面 (ゲームの計算) と画面は別々に動いています。`RestartCurrentGameMode` は盤面だけを
作り直すため、画面のパネルは自分では消えません。v3.9 では画面の部品を調べて、
閉じる処理 (`Hide` / `Close` など) か `SetActive(false)` でパネルを閉じにいきます。
- 何も出ない → ゲームオーバーの判定ができていません ([ゲームオーバーのログ](#ゲームオーバーのログ) の
  確認手順を見てください)。

## 実行ログ (LCAC-2048.log)

`[2048-auto] ...` の行は `Documents/LCAC-2048.log` にだけ書かれます (コンソールには出ません。
1 MB を超えると作り直します)。アプリ自身のログ (広告 SDK・解析の再送) は入らないので、
症状を報告するときはこのファイルをそのまま添付してください。
同じ行が連続する場合は 100 回ごとに 1 行にまとめ、20,000 行で打ち切られます。

- `milestone tile=8192 score=147528 moves=3210 board ...` — 2,048 / 4,096 / 8,192 … を作れた時点の記録。
  `moves` はそこまでのスワイプ回数、`board` はゲームオーバーの記録と同じ並び (1 行目が画面の一番下)。
- `moves=` はゲームオーバーの記録にも入ります。実機とシミュレーションの手数を比べるのに使えます。

## ゲームオーバーのログ

ゲームオーバーになると、アプリの `Documents/LCAC-2048_over.log` に最終盤面を追記します
(1 ゲーム 1 ブロック、dylib の版・時刻・スコア・盤面)。

取り出し方:

- Files アプリで、2048 のコンテナ (LiveContainer の場合は LiveContainer 内のデータ) の
  `Documents` を開く
- あるいは `idevicecontainer` などで該当アプリの `Documents/LCAC-2048_over.log` をコピーする

ファイルができないときは、次を確認してください。

- 本当にゲームオーバーになったか (AUTO が `PAUSE` になっただけでは書かれません。
  手が 1 つでも残っていると書きません)
- `[2048-auto] game over: board saved` がログに出ているか。出ていれば書き込みは成功しています
- 出ていない場合: そのゲームはまだ手が残っているか、`F_MGR` / `V_GRID` などで盤面を読めていません

### 2048 の達成画面で止まる

仕様です。達成画面では `PAUSE` になり、`AUTO` が ON のまま「続ける」を押すと自走が再開します。
「続ける」を押したくない場合は、先に `AUTO` を OFF にしてください。

## 状態表示の一覧

`AUTO` ボタンの 2 行目に出る文字列です。太字は自動停止 (AUTO が OFF に戻る) するものです。

| 表示 | 意味 | 対処 |
| --- | --- | --- |
| `OFF` | 自走停止 | `AUTO` をタップして開始 |
| `START` | 開始直後 | そのまま待つ |
| `ON` | 1 手操作した | そのまま待つ |
| `THINK` | 盤面を探索中 | そのまま待つ |
| `STALE` | 盤面などが変化したため結果を破棄 | そのまま待つ (次のフレームで再探索) |
| `MODE` | 対象外のモード (通常ゲーム以外) | 通常ゲームを開く |
| `PAUSE` | ゲームが非アクティブ | ゲームに戻る / 「続ける」 |
| `V_MOVE` | タイル移動中 | そのまま待つ |
| `V_GRID` | 表示中の盤面が取得した盤面と違う | そのまま待つ (画面遷移中) |
| `V_NULL` | 表示側のインスタンスが未取得 | そのまま待つ。続くなら Issue へ |
| `I_START` / `I_API` | IL2CPP の API を解決中 / 見つからない | 見つからない場合はゲーム側の構成が違う。Issue へ |
| `I_UNITY` | UnityFramework がまだ初期化されていない | タイトル画面などで待つ。続くなら Issue へ |
| `I_CLASS` | IL2CPP のクラスが見つからない | 2048 のバージョンを確認 (4.0.8 のみ対応) |
| `I_METHOD` | IL2CPP のメソッド・フィールドが見つからない | 同上 |
| `F_MGR` | 管理オブジェクト (`GameManager`) が未取得 | 通常ゲームを開く。続くなら Issue へ |
| `G_NULL` | 盤面 (`Grid`) が未取得 | ゲームを開始する。続くなら Issue へ |
| `F_EXC` / `G_EXC` / `V_EXC` | 対応する内部呼び出しで例外 | ゲームを再起動。続くなら Issue へ |
| **`END`** | 合法手なし (ゲームオーバー) | ゲームを終了して新しいゲームを開始 |
| **`SIZE`** | 盤面が 4×4 でない | 盤面サイズを 4×4 に戻す |
| **`DATA`** | 想定外の盤面値 (2 の累乗以外) | ゲームを再起動。続くなら Issue へ |
| **`ERR`** | 内部エラー | ゲームを再起動 |

## ログ

専用のログファイルは作りません。`NSLog` の出力を次の方法で確認してください。

- Mac: Console.app でデバイスを選び、`2048-auto` で検索
- それ以外: `idevicesyslog` などで `[2048-auto]` を検索

主な出力は `IL2CPP ready` (解決成功)、`API missing: <name>` (API が見つからない)、
`class manager=... methods=...` (クラス・メソッドの解決失敗)、`managed exception` (内部例外) です。

## Issue に書いてもらえると助かること

- 端末と iOS のバージョン
- 2048 のバージョン、LiveContainer のバージョン
- `AUTO` ボタンに出ていた状態表示
- 再現手順 (通常ゲームを開いてから何をしたか)
- 上記のログの抜粋

ゲームのアカウント情報、セーブデータそのもの、個人情報は書かないでください。
